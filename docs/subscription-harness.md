# Yogurt: agy, Porch и русский язык

В этом форке свежий профиль Yogurt использует **agy → Gemini 3.8 Flash → medium** для расшифровки аудио и всех текстовых функций. В настройках можно выбрать точные профили Porch либо вернуться к локальным моделям.

В режимах agy и Porch **GGUF, Whisper, Apple Speech и embedding-модели не скачиваются**, GPU не проверяется и локальный llama не запускается. Записи и заметки хранятся на компьютере, а аудио и текст для обработки отправляются выбранному провайдеру. Название «режим подписки» обозначает использование внешнего CLI; оно не гарантирует доступность модели, квоты или право использовать конкретный тариф в стороннем приложении.

## 1. Установите и авторизуйте CLI отдельно

Установите Antigravity CLI по [официальной инструкции Google](https://antigravity.google/docs/quickstart?tab=cli). Используйте версию с `stream-json` и выбором `--effort`; контракт Porch, использованный при разработке, требует agy 1.5.4 или новее.

Проверьте версию и выполните вход:

```sh
agy --version
agy acp --login
```

Другой документированный способ входа — интерактивный запуск `agy`. [Официальная инструкция ACP](https://antigravity.google/docs/cli/acp) описывает оба варианта. Вход выполняется один раз вне Yogurt; приложение не запрашивает пароль, OAuth-токен или API-ключ и не меняет хранилище учётных данных.

Наличие agy само по себе не означает оплату через подписку: [настройки Antigravity](https://antigravity.google/docs/install?tab=cli) также поддерживают режим API-ключа. Прямой agy-адаптер Yogurt выбирает вход через аккаунт только для своего дочернего процесса, отключает использование дополнительных G1 credits и исключает переменные `GEMINI_API_KEY`, `GOOGLE_API_KEY`, `AGY_ADC_AUTH`. Он не меняет постоянные настройки CLI и не переходит на API-ключ при ошибке. Профили Porch сохраняют собственную авторизацию: для них отдельно выберите вход через подписочный аккаунт. Yogurt удаляет из окружения дочернего процесса Porch ключи API провайдеров и унаследованные переопределения модели и уровня рассуждения, поэтому профиль должен работать через вход в аккаунт подписки своего CLI. При запуске из Finder явный путь к исполняемому файлу передаётся только профилям agy; для остальных CLI они должны находиться в PATH графического окружения.

Совместимость тарифа проверяется отдельно: на 15 ноября 2026 года [FAQ Antigravity](https://antigravity.google/docs/faq) указывает, что обёртки над CLI в сторонних приложениях не поддерживаются на потребительских тарифах. Этот форк не обходит ограничения провайдера и не подтверждает пригодность вашего аккаунта.

## 2. Запустите этот форк

Из корня своего checkout, с Node.js 24 и pnpm 10.7.0:

```sh
pnpm install --frozen-lockfile
pnpm -C app native
pnpm dev
```

Нативные зависимости для записи звука по платформам перечислены в [инструкции сборки](building.md). Отсутствие скачивания AI-моделей не отменяет установку самого CLI и зависимостей сборки.

Готовые установщики upstream FrigadeHQ/yogurt не содержат изменений этого форка.

Автоматические обновления из upstream отключены, чтобы официальный релиз не заменил интеграцию провайдеров. Новую версию этого форка нужно собрать или установить отдельно.

Откройте **Настройки → Обработка ИИ**. Даже если agy ещё не установлен, приложение позволяет открыть настройки. Для прямого agy оставьте:

| Поле | Значение |
| --- | --- |
| Режим обработки | agy · Antigravity CLI |
| Модель расшифровки | `gemini-3.8-flash` |
| Рассуждение при расшифровке | `medium` |
| Модель для текста | `gemini-3.8-flash` |
| Рассуждение для текста | `medium` |
| Исполняемый файл agy | `agy` или абсолютный путь к исполняемому файлу |
| Тайм-аут запроса | 600 секунд по умолчанию |
| Объём входного контекста | 32768 токенов по умолчанию |

**Проверить CLI** проверяет только наличие исполняемого файла и его версию. Проверка не отправляет аудио или текст модели, не подтверждает вход в аккаунт, наличие Gemini 3.8 Flash или условия тарифа.

Нажмите **Сохранить изменения**, затем **Перезапустить Yogurt**. До перезапуска используется конфигурация из строки «Сейчас используется». При незавершённой записи, расшифровке или другой текущей работе перезапуск отклоняется; сохранённые настройки остаются для следующего запуска. Сохранение само по себе не останавливает запись и не переключает провайдера.

Пути к CLI — это имена исполняемых файлов или абсолютные пути, без `--flag`, конвейеров и shell-команд. Если приложение запущено из графического меню и не видит PATH терминала, исполняемый файл ищется по имени в PATH, затем в `~/.local/bin`, `/opt/homebrew/bin` и `/usr/local/bin` (в этом порядке); проверка CLI показывает найденный абсолютный путь, а если его там нет, укажите путь явно. Изменения в настройках не устанавливают CLI и не выполняют вход.

Для запуска можно также задать `YOGURT_AI_BACKEND`, `YOGURT_AGY_PATH` и `YOGURT_PORCH_PATH`. Например:

```sh
YOGURT_AI_BACKEND=agy YOGURT_AGY_PATH=/absolute/path/to/agy pnpm dev
```

Если переменные окружения заданы, они переопределяют соответствующие сохранённые значения при следующем запуске. В интерфейсе перечислены такие переменные; обычный перезапуск не снимает их действие. Для управления только из интерфейса уберите эти переменные из команды запуска.

## 3. Русская речь, интерфейс и ответы

Это независимые настройки:

| Что нужно изменить | Где выбрать |
| --- | --- |
| Язык речи в записи (по умолчанию — мультиязычный режим) | Настройки → Язык → Язык речи; также меню языка в заметке |
| Русский интерфейс | Настройки → Язык → Язык приложения → Русский |
| Русские конспекты и ответы | Настройки → Обработка ИИ → Язык ответов ИИ → Русский |
| Исходный язык создаваемого текста | Язык ответов ИИ → Автоматически |

Расшифровка сохраняет язык речи и не переводит аудио. По умолчанию Yogurt определяет язык сам (Мультиязычный режим); явный выбор «English only» или «Русский» записывается в настройки и не меняется. В автоматическом режиме конспекты и заголовки следуют основному языку встречи, а ответы — языку вопроса. Принудительный язык ответов относится к создаваемому тексту, а не к интерфейсу или аудио.

Настройки провайдеров этого форка переведены на русский и английский. При другом языке интерфейса этот раздел использует английский; остальные части приложения сохраняют существующие переводы.

## 4. Porch: отдельный профиль для аудио и текста

Установите [pragmatic-orchestration / Porch](https://github.com/CodeAlive-AI/pragmatic-orchestration) и авторизуйте каждый выбранный backend его собственным CLI. Для Porch нужны его обычные зависимости, включая Python 3 и Bash. **Адаптеры Yogurt передают готовый WAV без перекодирования и не требуют ffmpeg или ffprobe.** Адаптер Porch в этом форке работает на macOS и Linux. В Windows выберите прямой agy и укажите нативный `.exe`; shell-обёртки `.cmd`, `.bat` и `.ps1` не поддерживаются.

Проверьте доступные точные профили:

```sh
porch --list-agents
porch media capabilities --json
```

В Yogurt выберите режим **Профили Porch**:

- **Профиль расшифровки:** один точный ID, например `agy-gemini-3.8-flash`. Его backend должен быть `antigravity-cli` / agy с нативным аудиовходом. Текстовый профиль Codex или Claude нельзя использовать вместо аудиомодели.
- **Профиль для текста:** один точный ID профиля Porch, который вы установили и настроили. Он применяется к конспектам, заголовкам, переписыванию, вопросам по одной или нескольким встречам и предложениям папок. Доступность конкретного backend зависит от установки и аккаунта.
- **Модель расшифровки / рассуждение:** `gemini-3.8-flash` / `medium`. Yogurt передаёт эти значения как `AGY_MODEL` и `AGY_EFFORT` только аудиовызову Porch. У штатного профиля `agy-gemini-3.8-flash` уровень по умолчанию может быть `high`, поэтому переопределение существенно.
- **Текст:** модель и уровень рассуждения определяются выбранным профилем Porch. Настройте профиль на `medium`, если это нужно и для текста; поля прямого agy не переопределяют произвольный текстовый backend.
- **Исполняемые файлы:** `porch` и `agy` либо их абсолютные пути. Это должны быть исполняемые файлы, а не shell aliases.

Полный ID профиля выбирается явно: списки, wildcard-выбор и дополнительные аргументы в поле профиля не принимаются. Пользовательский `config.json` / `PORCH_CONFIG` заменяет штатный пример Porch, поэтому нужный профиль может потребоваться добавить в вашу конфигурацию.

### Контракт интеграции

Совместимость проверялась по исходникам Porch на commit **`b0c5cf4d5d236677595a508ee3491d56ae1e0e8a`**, а не по обещанию стабильности внутреннего API.

Аудио и текст обрабатываются через внутренний runner рядом с реальным исполняемым файлом Porch:

```text
bash <porch-directory>/lib/backend_run.sh
  --mode media
  --agent-id <exact-profile-id>
  --raw
  --prompt-file <temporary-prompt-file>
```

Для аудио сначала проверяется присутствие точного профиля в списке `transcribe`, возвращаемом `porch media capabilities --json`. Это проверка конфигурации, без запроса к модели. В рабочей папке лежит исходный `audio.wav`; JSON-схема передаётся через `PORCH_OUTPUT_SCHEMA`, модель и уровень рассуждения — через `AGY_MODEL` и `AGY_EFFORT`. Русский язык и словарь встречи включаются в запрос.

Так сохраняется исходная длительность WAV и проверяются необработанные модельные таймкоды. Публичная команда Porch `media transcribe` предназначена для произвольных медиафайлов: она перекодирует их и нормализует таймкоды, что здесь нарушило бы привязку к времени встречи. Для текста выбранный профиль сохраняет свою модель и уровень рассуждения.

Режим `--raw` сохраняет запросы Yogurt без ролей и шаблонов команды `porch review ask`. Внутренний runner может измениться в будущих версиях Porch; при несовместимости обновите адаптер или используйте совместимую версию. Профили сохраняют инструменты и разрешения своих backend; режим `media --raw` не обеспечивает одинаковую изоляцию shell/web-инструментов для всех провайдеров.

Справочные исходники: [конфигурация Porch](https://github.com/CodeAlive-AI/pragmatic-orchestration/blob/b0c5cf4d5d236677595a508ee3491d56ae1e0e8a/skills/pragmatic-orchestration/references/configuration.md), [media.py](https://github.com/CodeAlive-AI/pragmatic-orchestration/blob/b0c5cf4d5d236677595a508ee3491d56ae1e0e8a/skills/pragmatic-orchestration/scripts/lib/media.py), [backend_run.sh](https://github.com/CodeAlive-AI/pragmatic-orchestration/blob/b0c5cf4d5d236677595a508ee3491d56ae1e0e8a/skills/pragmatic-orchestration/scripts/lib/backend_run.sh).

## Тишина на дорожке собеседника

Если во время звонка звук компьютера перестаёт записываться (дорожка «собеседника» идёт цифровой тишиной), Yogurt замечает это сам и чинится без участия пользователя:

- Нативный помощник записи следит за точными нулями на дорожке «собеседника». После 20 секунд тишины, пока в системе играет чужой звук, он сам пересоздаёт системный tap с экспоненциальной паузой (40 с, 80 с, до 5 минут). Это самолечение не зависит от настроек приложения.
- Приложение дублирует контроль: на 60-й секунде тишины при признаках чужой речи (сигнал читалки звонка или речь в микрофоне) оно просит помощника пересобрать tap; ещё через 30 секунд, если звука нет, показывает предупреждение — компактное в плавающем виджете записи и полное под заметкой, плюс одно системное уведомление за встречу.
- В баннере две кнопки: «Перезапустить захват звука» и «Не предупреждать на этой встрече» (для текущей встречи; «Вернуть» отменяет). После трёх неудачных автопересборок уведомлений больше нет — решение за пользователем.
- Вебинары и разговоры с самим собой не предупреждают: один участник в звонке и режим, где читалка видит только вашу речь, тревогу не вызывают.
- Настройки → Запись → «Предупреждать, если не слышно собеседника» (включено по умолчанию) отключает баннер, уведомление и прикладные пересборки; самолечение помощника продолжает работать.
- Если тишина суммарно превысила 2 минуты, заметка после встречи спокойно сообщает диапазоны в записи — без аудио, только таймкоды.

## Данные и ограничения

- Встречи, записи, расшифровки и заметки сохраняются локально. Во внешние CLI передаётся содержимое, необходимое для запрошенной AI-функции; провайдеры обрабатывают его удалённо по своим правилам. CLI может вести собственную историю и журналы.
- Учётные данные остаются у CLI. Yogurt хранит выбранный режим, пути, модели, профили, уровни рассуждения, язык и лимиты запросов.
- Для расшифровки передаётся реальное аудио, а не описание файла. Финальные сегменты привязываются к времени встречи; входящие микрофон и звук собеседников остаются раздельными дорожками.
- Локальные embedding-модели в режиме провайдера отключены. Поиск для вопросов по библиотеке использует слова и контекст выбранных встреч. Семантическое совпадение, русские словоформы и поиск вопросом на другом языке могут находить меньше источников, чем embedding-поиск.
- При ответе CLI только целиком текст появляется после финального результата; это не настоящий поток токенов. Частые локальные «черновые» распознавания и чтение текста наперёд отключены, чтобы не расходовать запросы провайдера.
- На прямом маршруте agy Yogurt удаляет копии разговоров, которые создал сам: после каждого запроса, успешного или неудачного, и при следующем запуске, если приложение завершилось посреди запроса. Из `~/.gemini/antigravity-cli` удаляются `conversations/<id>.db` вместе с её файлами `-wal`, `-shm` и `-journal`, `brain/<id>/` (вторая копия аудио и журналы), `presence/<id>.lock` и `annotations/<id>.pbtxt`. Разговор считается созданным Yogurt только если id напечатал в событии init сам процесс запроса и база данных создана не раньше этого запуска; ваши собственные разговоры в agy не затрагиваются. Если agy не сообщил id, копия остаётся, а Yogurt пишет предупреждение в свой журнал. Маршрут Porch такой очистки не выполняет: копии аудио остаются в его хранилище.
- Удалённая расшифровка отправляет провайдеру аудио порциями до 5 минут звука на запрос: запуск CLI стоит десятки секунд, и одна длинная порция дешевле серии коротких. Первую порцию каждой дорожки приложение отправляет примерно через минуту после того, как на ней пошла речь, а следующие — примерно раз в пять минут. Текст появляется частями с задержкой в минуту и более — это ожидаемое поведение, а не зависание. Аудиозапросы используют тайм-аут не меньше 600 секунд. Уровень рассуждения `low` для расшифровки недоступен: на практике он обрезал конец длинного аудио. Доступны `medium` и `high`; сохранённое ранее значение `low` загружается как `medium`. Фрагмент, в котором чётко различимой речи почти нет, отправляется без имён и словаря встречи: на шуме без речи модель способна выдумать текст из них. Аудио не отбрасывается.
- Ошибка или тайм-аут не включает скрытый переход к локальным моделям. Незавершённая расшифровка помечается как ожидающая. Каждая поставленная в очередь порция аудио сохраняется на диске в папке встречи (`pending-audio/`) и удаляется только после того, как её строки записаны в расшифровку; выход из приложения или сбой между отправкой и сохранением ничего не теряет. При следующем запуске оставшиеся порции отправляются повторно в фоне (не больше трёх автоматических попыток на порцию), а кнопка «Повторить» на заметке отправляет все, включая исчерпавшие попытки; отметка «расшифровка неполная» снимается, когда очередь на диске пуста. Повторная отправка идёт тем же конвейером пакетной расшифровки, но восстановленные строки передаются на замороженном языке встречи, не проверяются на эхо относительно другой стороны и не получают имён участников звонка. Повторение — как минимум один раз: сбой между сохранением строк и удалением аудио с диска может продублировать одну порцию. Баннер «расшифровка неполная» показывается, только когда аудио действительно ждёт отправки: не во время обычного дожима после «Стоп» и не на локальном Whisper.
- Лимит контекста — консервативный бюджет приложения, а не подтверждение лимита выбранной модели. Вместо недоступного CLI-токенизатора используется верхняя оценка по UTF-8-байтам с учётом JSON-экранирования и отдельным резервом для служебного текста. Поэтому встречи могут разбиваться на части раньше, чем при точном подсчёте токенов. Для больших встреч конвейер составляет промежуточные конспекты, сохраняя кириллицу и разрезая длинную речь по предложениям или словам.
- Если после создания конспекта в контекст не помещается дополнительная проверка следующих шагов, готовый конспект сохраняется. Основной запрос уже включает следующие шаги. Заголовок в таком случае можно получить из полного конспекта без повторной передачи расшифровки.
- Автоматизированные проверки используют подставные CLI. Сквозной запуск на живом аккаунте, качество русской речи, квоты, задержка и поведение конкретной версии agy/Porch должны быть проверены отдельно. Успешная кнопка «Проверить CLI» этого не доказывает.

Результаты выполненных проверок: [отчёт о валидации](subscription-validation.md).

Порядок проверки на настоящих аккаунтах и записях: [план живой верификации](live-verification-plan.md). Он включает границы длительности аудио, реальные маршруты agy/Porch, русский корпус, сохранение данных, отказы и длительные встречи; план не является отчётом о выполненных live-тестах.

## Возврат к локальной обработке

Выберите **Локальные модели**, сохраните настройки и перезапустите Yogurt. Снова включатся исходные скачивания и аппаратные проверки, Whisper, локальная текстовая модель и embedding-поиск. Переключение провайдера не удаляет встречи или уже скачанные модели. Старые модели не используются в режиме agy/Porch. Принудительный язык ответов — настройка режима провайдера; в локальном режиме действует исходный выбор языка по встрече или вопросу.

## English quick reference

Fresh profiles use **agy / `gemini-3.8-flash` / `medium`** for transcription and text. Install and sign in to the CLI separately (`agy acp --login`, or an interactive `agy` session), build this fork, then open **Settings → AI processing**. Save changes and restart; a running session retains its active configuration. **Check executable** tests presence/version only.

Provider modes send audio/text to the selected providers and skip all local model downloads, GPU checks, Apple Speech downloads and local llama execution. Local storage does not mean local AI processing. Provider plan eligibility and support are separate from CLI availability; Google’s current FAQ says third-party app wrappers are unsupported under consumer plans.

Porch audio requires an exact profile listed by `porch media capabilities --json` as supporting transcription. Both audio and text use the pinned internal `backend_run.sh --mode media --raw` contract. Audio passes the original WAV and JSON schema without transcoding, so ffmpeg is not required; the app overrides its audio model/effort with the transcription fields. Text uses the chosen profile’s own model/settings. Profile tool permissions still apply. Library retrieval is keyword-based without embeddings, and final-only CLI output is not token streaming. Real-account end-to-end quality is not claimed by the automated tests.
