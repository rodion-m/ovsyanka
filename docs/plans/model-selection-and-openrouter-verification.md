# План проверки: выбор моделей и OpenRouter

К плану `docs/plans/model-selection-and-openrouter.md` (этапы 0–8). Составлен 18 ноября 2026 года по правилам pragmatic-verification: на каждый риск — самая дешёвая проверка, которая содержит механизм возможной ошибки и даёт увидеть правильный результат.

## Уровень строгости

Работа затрагивает **секрет пользователя** (ключ OpenRouter), **передачу аудио и текста встреч третьей стороне** и **деньги** (оплата за запросы). Поэтому по правилам «дорого ошибиться»: отрицательные случаи на границе главного процесса, настоящее хранилище (`safeStorage`/Связка ключей) хотя бы в одной проверке, независимое ревью каждого этапа с ключом или сетью, явный остаточный риск в отчёте.

Экран выбора моделей (этапы 1–3) — функциональное изменение: маршрут целиком, но без отдельного ревью безопасности.

## Общие правила для исполнителей

1. **Источник ожидаемого (оракул)** — план, эта таблица, документация OpenRouter, снимок живого ответа `/models` от 18.11.2026 (сохраняется в `app/test/fixtures/` как есть, урезанный только по числу записей, не по полям) и посчитанные вручную примеры. Никогда — вывод проверяемого кода. Ожидаемые числа отбора на полном снимке взяты из плана (4.3, 4.4); если на сохранённом снимке они другие, исполнитель останавливается и сообщает, а не подгоняет.
2. **Граница модели.** Хотя бы один тест на каждый вид ответа начинается с сырого ответа в форме OpenRouter (тело HTTP, как в документации) и проходит через настоящий адаптер и настоящий `parseTranscript`. Подставной объект «готовая расшифровка» проверяет только конвейер.
3. **Текст запроса.** Проверяется собранный запрос: язык, словарь (или его отсутствие при малой чёткой речи), нет незаполненных подстановок. Сборщик запроса не подменяется.
4. **Красный хотя бы раз.** Для каждого правила безопасности и каждого правила отбора исполнитель один раз ломает правило в коде (убирает удаление ключа из журнала, меняет `>=` на `>` в отборе по контексту), видит красный тест, возвращает. В отчёте — какое правило ломали и какой тест покраснел.
5. **Запрещено:** считать ожидаемое тем же кодом; ассерты по числу внутренних вызовов, кроме обещанного внешнего эффекта (число HTTP-запросов при повторах — обещанный эффект); пустые циклы `every` без проверки непустоты; ослабление существующих ассертов. Красная проверка — значит не прав код, тест или спецификация; выяснить, кто.
6. **Где запускается.** Типы и тесты затронутых файлов — на Mac через `mac-heavy`. Полный набор тестов и сборка `electron-vite build` — на VM `dev-docker-sg` после каждого влитого этапа. Сборка приложения и проход по нему — на Mac через `mac-heavy`.

## Этап 0. Живой OpenRouter (без кода приложения)

Это не тесты продукта, а получение фактов, которые станут оракулом для этапов 4 и 7.

| Вопрос | Как отвечаем | Что фиксируем |
| --- | --- | --- |
| Проходит ли 5 минут WAV (12,8 МБ base64) в `/chat/completions` | 3 запроса: 15 с, 1 мин, 5 мин | статус, время, размер тела |
| Соблюдается ли строгая схема | те же ответы через тот же `parseTranscript` (скрипт импортирует его из `app/src`) | доля ответов, прошедших разбор |
| Точность таймкодов | синтетическая русская запись с известной разметкой из прежних проверок (`evidence/w3l-long-batch`) | медиана и максимум отклонения середины фразы |
| Выдумки на шуме | 3 записи шума × со словарём / без | число непустых ответов |
| STT-модели | 3–4 модели разных провайдеров, `verbose_json` | есть ли `segments`, насколько таймкоды выходят за длительность |
| Формы ошибок | неверный ключ, несуществующая модель, `zdr` без провайдера | тела ответов (без ключа) |
| `GET /key`, `usage` | один запрос и поля `usage` из ответов выше | реальные поля, аудиотокены в секунду |

Результат — отчёт с цифрами и правки плана. Ключ передаётся только переменной окружения запуска, не печатается и не пишется в файлы; после прогона отчёт и журналы проверяются поиском префикса `sk-or-v1-`. Бюджет — не больше $3; нужен ключ и согласие владельца.

## Этап 1. Настройки без противоречий

**Обещания:**
1. При запуске с `YOGURT_AI_BACKEND=agy` и сохранённом Porch экран показывает действующий режим agy, поле режима заблокировано с фразой и именем переменной, ниже — поля agy.
2. Сохранение других полей в таком состоянии **не меняет** сохранённый режим (запрещённый эффект: форма перезаписывает Porch на agy).
3. Без переменной: сохранено другое → строка «Сохранено: … применится после перезапуска» и кнопка «Перезапустить»; совпадает → одна строка.
4. Абзаца про переменные окружения больше нет.

| Механизм ошибки | Проверка | Уровень |
| --- | --- | --- |
| `ai:save` записывает заблокированное поле из формы | тест `ipc` с переменной окружения: сохранить форму, прочитать `settings.json` с диска | интеграция главного процесса, настоящий файл во временной папке |
| форма показывает сохранённое вместо действующего | компонентный тест `AiSettings` с `locked` | компонент, события пользователя |
| старое поле `environmentOverrides` где-то читается | `tsc` после удаления поля | типы |
| обе локали | существующие i18n-тесты | модуль |

Ломаем один раз: убрать защиту заблокированного поля в `ai:save` → тест 2 краснеет.

**Проход по продукту** (одноразовый, на Mac, после этапа 2): запуск с переменной и без, скриншоты строки состояния.

## Этап 2. Компонент выбора и перечень agy

**Обещания:**
1. Выбор модели мышью и только клавиатурой (`↓`/`↑`/`Enter`/`Esc`/`Tab`) по шаблону WAI-ARIA combobox.
2. Поиск по части ID и названия, несколько слов — все должны совпасть.
3. Свой ID: допустимый сохраняется и после перезапуска виден с меткой «свой ID»; недопустимый выбрать нельзя.
4. `Esc` возвращает прежнее значение (запрещённый эффект: незаметная смена модели).
5. Для расшифровки нет уровня `low`.

| Механизм ошибки | Проверка | Уровень |
| --- | --- | --- |
| неверная фильтрация и сортировка | таблица случаев для чистых функций `aiCatalog` (поиск, проверка своего ID: граничные символы `. - _ / :`, кириллица, пробел, 200 и 201 символ) | модуль |
| клавиатура, фокус, `aria-activedescendant`, объявление «Найдено N» | компонентный тест событиями клавиатуры | компонент (jsdom) |
| фокус и прокрутка списка в настоящем окне | один e2e Playwright в режиме `YOGURT_FAKE`: открыть настройки, выбрать свой ID клавиатурой, сохранить, перезапустить, увидеть значение | настоящий Electron |
| экранный диктор | проход VoiceOver вручную, один раз, с заметкой в отчёте | платформа; постоянным тестом не становится |

Существующие тесты, которые ищут `<input id="ai-transcriptionModel">`, переписываются на поиск по роли и подписи, а не удаляются; их обещание (значение по умолчанию `gemini-3.8-flash`) сохраняется.

## Этап 3. Списки Porch и `agy models`

**Обещания:**
1. В списке расшифровки только профили из `porch media capabilities` → `transcribe`.
2. Профили с недоступным CLI — в группе «Недоступные» с причиной.
3. Сломанный, пустой или неожиданный вывод CLI → понятное сообщение, встроенный список и свой ID; форма работает.
4. Porch или agy не установлен → понятная ошибка, приложение не падает.
5. Выбор профиля подставляет модель профиля.
6. Запуск из Finder с коротким `PATH` находит CLI.

| Механизм ошибки | Проверка | Уровень |
| --- | --- | --- |
| разбор `--list-agents` (экранирование XML, лишние атрибуты, строка без `id`, ноль строк) | таблица случаев на текстах; основной образец — настоящий вывод `porch --list-agents` с этой машины, сохранённый в фикстуру | модуль |
| разбор `agy models` (суффиксы уровней, строка «Fetching…», мусор) | таблица случаев; образец — настоящий вывод agy 1.5.11 | модуль |
| запуск CLI, тайм-аут 5 с, очищенное окружение, `PATH` | подставные CLI-скрипты во временной папке (как в `test/harness.test.ts`): медленный, падающий, печатающий мусор; проверка, что в окружение ребёнка не попали ключи (`GEMINI_API_KEY`, `YOGURT_OPENROUTER_API_KEY`) | интеграция главного процесса, настоящие процессы |
| настоящий Porch | один ручной прогон `ai.options({backend:'porch'})` на Mac, сравнение числа профилей с выводом CLI | реальная среда, одноразово |

## Этап 4. OpenRouter: ключ и адаптер

Самый рискованный этап. Обещания и запрещённые эффекты:

1. **Ключ нигде не появляется в открытом виде:** ни в `settings.json`, ни в `logs/main.log`, ни в резервной копии, ни в ответах IPC в окно, ни в тексте ошибок, ни в окружении дочерних agy/Porch.
2. Ключ хранится через `safeStorage`; если шифрование недоступно — не сохраняется вовсе (нет сохранения открытым текстом).
3. Ключ из другой сборки не читается → состояние «введите заново», приложение запускается.
4. Без ключа приложение запускается, настройки открываются, расшифровка ждёт с причиной `no-key`, аудио остаётся в `pending-audio/`.
5. Каждый ответ OpenRouter из таблицы 3.4 плана даёт свой `AiProblemCode`; повторяются только помеченные «да», не больше двух раз, с паузой из `Retry-After` (не больше 60 с).
6. Ответ аудиомодели проходит тот же `parseTranscript`, что и от agy; пакет с малой чёткой речью уходит без словаря.
7. `HTTP-Referer` и `X-OpenRouter-Title` не отправляются.
8. Отмена при выходе прерывает запрос.
9. Никакого скрытого перехода на другую модель, провайдера или локальный режим.

| Механизм ошибки | Проверка | Уровень и что настоящее |
| --- | --- | --- |
| ключ попадает в артефакты через текст ошибки, журнал, IPC | **сквозной тест-сторож**: известный поддельный ключ проходит сценарии «сохранить», «проверить», «ошибка 401», «ошибка 500 с телом, повторяющим заголовки», «выход»; затем поиск строки ключа и его хвоста из 8 символов во всех файлах временного `userData`, в перехваченных журналах и во всех ответах IPC | интеграция главного процесса; настоящие файлы; `fetch` подставной на уровне HTTP |
| ключ уходит в окружение дочернего процесса | подставной agy печатает своё окружение в файл; поиск ключа | настоящие процессы |
| `safeStorage` недоступен или не расшифровывает | подставной `safeStorage` с тремя состояниями; плюс **один ручной прогон с настоящим `safeStorage`** в собранном приложении на Mac (сохранить, перезапустить, ключ читается; сменить сборку — состояние «введите заново») | модуль + платформа |
| неверная классификация ошибок | таблица случаев: тело и статус взяты из документации и из этапа 0 (сырые ответы), через настоящий адаптер | интеграция адаптера, подставной HTTP |
| повторы | управляемые часы: 429 с `Retry-After: 3` → один повтор через 3 с; 401 → без повторов; три 503 подряд → два повтора и ошибка; число HTTP-запросов — обещанный эффект | интеграция адаптера |
| формат расшифровки | сырой ответ `/chat/completions` в форме документации (и из этапа 0) → адаптер → `parseTranscript` → строки встречи; плюс ответ с полем `error` при статусе 200 | граница модели |
| текст запроса | собранное тело запроса: есть язык, словарь присутствует при чёткой речи и отсутствует при `clearMs < 300`; аудио — тот же WAV (длина в байтах); заголовков атрибуции нет | интеграция адаптера |
| пакет теряется при ошибке | конвейер с адаптером, отвечающим `credits`: после пакета аудио осталось в `pending-audio/`, строк нет, баннер причины есть; после «Повторить» с исправным ответом строки появились, спул пуст | интеграция конвейера, настоящий спул на диске |
| отмена | долгий подставной ответ, `harness.stop()` → запрос прерван, пакет в спуле | интеграция |

Ломаем один раз: убрать удаление ключа из текста ошибки → сторож краснеет; разрешить повтор на 401 → тест повторов краснеет.

**Независимое ревью** этапа 4 (DeepSeek через Porch, без веб-поиска): утечки ключа, повторы, приватность.

## Этап 5. OpenRouter: список моделей

**Обещания:** отбор «для расшифровки» и «для текста» по правилам 4.3/4.4; сортировка «Новые»/«Дешёвые»; кэш 24 часа; ошибка сети не стирает кэш; без кэша и сети — пустой список с причиной и свой ID; оценка цены часа только в окне $0.005–$3.

| Механизм ошибки | Проверка | Уровень |
| --- | --- | --- |
| неверный отбор | на сохранённом снимке ответа: числа из плана (31+1 аудио, 30 STT, 316+14 текст) **и** таблица из 10–15 записей, классифицированных вручную (роутер `-1`, `openrouter/…`, `:batch`, `~`-псевдоним, `:free`, модель с истёкшей `expiration_date`, без `created`, без `endpoints`, с `context_length` 31 999 и 32 000, аудиовход без текстового выхода) | модуль, чистые функции |
| сортировка | маленький список с совпадающими датами и отсутствующими ценами | модуль |
| цена часа | посчитанные вручную примеры: `google/gemini-3.8-flash`, `openai/whisper-1` ($0.36/ч), `microsoft/mai-transcribe-2` (оценки нет) | модуль |
| кэш и сеть | временный `userData`, подставной `fetch`: свежий кэш не запрашивает сеть; старый — запрашивает в фоне; ошибка 500 и тайм-аут 15 с не меняют файл; битый JSON кэша игнорируется; не чаще раза в 2 минуты | интеграция с настоящим файлом, управляемые часы |
| изменение схемы OpenRouter | запись с лишними неизвестными полями и запись без необязательных полей проходит | модуль |

Ломаем один раз: `context_length > 32000` вместо `>=` → случай 32 000 краснеет.

## Этап 6. OpenRouter: интерфейс

**Обещания:** первый запуск (вставка ключа → автопроверка → значения по умолчанию → сохранение → перезапуск); неверный ключ и ключ другого сервиса; замена и удаление; флажок «та же модель» и его выключение для STT; список из кэша без сети; пропавшая модель; плашки `credits`, `auth`, `model-gone` на заметке и их снятие после успеха; клавиатура и VoiceOver; обе локали.

| Механизм ошибки | Проверка | Уровень |
| --- | --- | --- |
| логика формы, состояния, тексты ошибок | компонентные тесты событиями пользователя; `fetch` и IPC подставные | компонент |
| ключ задерживается в состоянии React или в DOM после отправки | компонентный тест: после отправки поля нет значения в DOM и в состоянии; IPC отдаёт только последние 4 символа | компонент |
| весь путь в настоящем окне | 2 e2e Playwright с подставным сервером OpenRouter на `localhost` (адрес базового URL подменяется только в тестовой сборке): «первый запуск до успешной расшифровки фрагмента» и «кредиты кончились → плашка → пополнили → Повторить → строки» | настоящий Electron, подставной сервер |
| существующий тест «нет `type="password"`» | ограничить его режимами без ключа, а не удалить; обещание (нет полей пароля там, где ключа нет) сохраняется | компонент |

**Проход по продукту** (одноразовый, на Mac, собранное приложение, настоящий OpenRouter, ключ владельца): вставить ключ, выбрать модели из живого списка, «Проверить» для обеих, короткая запись с YOGURT_FAKE, плашка при неверном ключе. Наблюдать конечный эффект: строки встречи и заметка, а не тост.

## Этап 7. OpenRouter: модели STT

Зависит от фактов этапа 0. Обещания: модель без `segments` нельзя сохранить; таймкоды за длительностью обрабатываются по правилу, принятому по данным этапа 0; тишина и шум не дают строк (фильтр `isSilenceGuess`); язык передаётся кодом ISO; расход по `usage.seconds` и `usage.cost`.

| Механизм ошибки | Проверка | Уровень |
| --- | --- | --- |
| ответ без `segments` превращается в один кусок без времени | сырой ответ `json` вместо `verbose_json` → ошибка `no-timestamps`, строк нет | граница модели |
| выход таймкодов за длительность | сырые ответы с выходом в пределах и за пределами допуска (значения из этапа 0) | граница модели |
| выдумки Whisper на тишине | сырой ответ с типичными выдумками («Продолжение следует…», «Thank you for watching») на тихом фрагменте → строк нет | модуль + граница |
| 25 МБ / 60 с | пакет больше предела отклоняется до отправки или режется по правилу из этапа 0 | интеграция адаптера |

## Этап 8. Живая проверка

Встреча 10–20 минут в режиме OpenRouter по сценариям `docs/live-verification-plan.md` с настоящим микрофоном: расшифровка обеих сторон, конспект, вопросы, выход сразу после «Стоп», повтор. Наблюдаемое: строки в базе по обеим дорожкам, их язык, задержка (из `TIMING`), расход по `usage.cost` против показанной оценки, отсутствие ключа в журналах. Повторить сценарий шума (3 прогона) и посчитать выдумки.

## Что останется недоказанным даже после всех этапов

- Качество расшифровки разных моделей OpenRouter на настоящих встречах: только наблюдения на нескольких встречах, не гарантия.
- Поведение провайдеров за OpenRouter при правиле `deny`/`zdr`: проверяется только то, что поле запроса отправлено; соблюдение правил на стороне провайдера проверить нельзя.
- Изменения схемы и цен OpenRouter после 18.11.2026: тесты закрепляют разбор снимка, а не будущие ответы.
- Поведение `safeStorage` в подписанной сборке для распространения (сейчас проверяется только неподписанная).

## Отчёт исполнителя по каждому этапу

Для каждого обещания этапа: статус (**проверено**, **частично**, **не проверено**, **заблокировано**), что именно запускалось, на какой ревизии, какое правило ломали и какой тест покраснел, что осталось за подменами. Написать тест, запустить его и показать, что он может упасть, — три разных факта.
